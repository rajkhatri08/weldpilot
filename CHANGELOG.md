## [Unreleased]

### Added

- Project skeleton: uv package with a src layout for Python 3.12 and the subpackages `data`, `detect`, `cause`, `act`, `edge`, `eval` and `report`.
- `weldpilot info` command: package version, Python version, git commit (with `-dirty` for uncommitted changes) and data root.
- Settings from the environment: `WELDPILOT_DATA` sets the data root (default `./data`).
- Ruff, mypy (strict) and pytest config; pre-commit hooks; GitHub Actions CI.
- README, ADR template, ADR 0001 (Python and tooling), datasheet outline and the Apache-2.0 licence.
- `weldpilot data verify` command: one SHA-256 fingerprint over the Al5083 release (train/, test/ and README; `.DS_Store` files and the `al5083/` copy are skipped). `--record` saves it to `configs/dataset.yaml`; otherwise a mismatch is an error.
- `weldpilot data index` command: checks the fingerprint first, then writes frame, segment and session tables to `data/derived/` from paths, labels and training PNG headers, with strict checks on names and labels. Test images are never opened.
- `weldpilot data composition` command: markdown tables of the release by split and by class, flagging classes with fewer than two train-only sessions.
- Datasheet Composition section, generated by `weldpilot data composition`.
- `weldpilot onset pick` command: picks up to `--n` training sessions with a good-to-fault change at random (`--seed`), spread across fault classes, and starts `data/annotations/onset_marks.csv` for marking onsets blind. It prints counts only and refuses to overwrite the file without `--force`.
- `weldpilot onset sheets` command: draws a label-free contact sheet for each training session in `onset_marks.csv` in `reports/onset_sheets/`: every 5th frame of each unbroken run, with its frame number, and a red tile for each gap. Other sessions are refused before anything is drawn.
- `weldpilot audit labels --unblind` command: audits the operator's labels of the training sessions into `reports/audit/`. It writes `label_timelines.png`, one strip per session in frame-number order coloured by class with gaps left blank. It writes `labels_summary.csv`: frames, labels in time order, label changes and gaps longer than 10 frames, per session. And it writes `labels.md`: sessions that change label, good-to-fault changes with frames missing just before them, and the onset marks against the operator's onset per pass, in frames and seconds (55 fps assumed), with n. Without `--unblind` it refuses before reading anything, because the outputs show the labels of the sessions marked blind.
- `weldpilot audit duplicates` command: a leakage audit with perceptual hashes. It hashes every frame, test frames included (data rule 2 allows this for the leakage audit), with a 64-bit DCT pHash cached in `data/derived/phash.parquet`: the first run hashes in several processes, and a rerun hashes again only the frames whose size or modification time changed. An exact pigeonhole search, instead of comparing all pairs, finds every pair within 4 bits across the split and between training sessions. It writes `reports/audit/duplicates.csv` (no labels) and `duplicates.md`: pairs by kind; exact copies, found by comparing the SHA-256 of the files of training-vs-test pairs with identical hashes, with their paths; the busiest session pairs, flagged frames by class with the sessions marked blind left out, and the search cost. A thumbnail shows the training frames of the closest pair per session pair; test frames are never drawn.
- `pandas-stubs` and `types-PyYAML` in the dev group, for mypy.
- `WELDPILOT_REPORTS` sets the reports folder (default `./reports`), as `WELDPILOT_DATA` sets the data root.
- Provenance files in `reports/provenance/`: `onset sheets`, `audit labels` and `audit duplicates` each write one JSON file naming their outputs, the git SHA (read before any long step), the dataset fingerprint and `"config": "no config"`.

### Changed

- `git_sha` moved from `weldpilot.cli` to the new `weldpilot.provenance`.
- Data rule 2 in `CLAUDE.md` allows SHA-256 checksums of test files for the leakage audit too, not only for the dataset fingerprint.
- Plain `uv run pytest` leaves out the `data` tests, as CI does; `uv run pytest -m data` runs them. Every run lists failures, errors and skip reasons.
- The image guards of `onset sheets` and `audit duplicates` also require a frame's path to lie in `train/`, not only its split column to say train.
- One reader for `onset_marks.csv`, `onset.read_marks`: `marked_sessions` now drops spaces around ids, as `parse_marks` already did.

### Fixed

- `onset pick` read the git SHA after writing the marks file, so the SHA it printed always ended in `-dirty`.
- Claims the code didn't back: the colour-separation figures in `label_timelines.py` are gone, the pHash test now checks against values from imagehash, and the duplicate audit's entry says what the cache does instead of how fast a rerun is.
